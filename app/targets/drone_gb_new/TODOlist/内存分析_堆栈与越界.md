# 内存分析 — 堆栈使用与越界风险

> 审查日期: 2026-05-23 | 目标: drone_gb_new | MCU: STM32F407IGHx (128KB RAM)

---

## 一、栈分析

### 配置

| 项目 | 值 |
|------|-----|
| 栈大小 | **8 KB** (0x2000) |
| 栈顶 | 0x20020000 (RAM 末尾) |
| 栈增长方向 | 向下 |

### 最坏路径深度

调用链: `TIM13 ISR → GimbalControl() → ComputeFf()`:
- 硬件上下文保存: ~32 B
- HAL 中断开销: ~48 B
- `GimbalControl()` 局部变量: ~48 B
- `ComputeFf()`: `Eigen::Matrix<float,2,9>` (72 B) + 临时变量 (~60 B) = ~132 B
- PID::Update × 4: ~192 B
- 其他 (IMU, AHRS, 电机 SetCurrent): ~160 B

**最坏路径总计: ~1.2 KB**

### 嵌套 ISR 最坏情况

如果所有 ISR 配置不同优先级（当前默认相同，不嵌套）:
- 主循环 + UART ISR + CAN ISR + 500Hz 定时器 ISR = **~1.5 KB**

### 结论

8 KB 栈，最坏 1.5 KB，**安全余量 ~6.5 KB**。无大栈数组、无递归、无深层嵌套。

## 二、堆分析

### 配置

| 项目 | 值 |
|------|-----|
| `_Min_Heap_Size` (链接器声明) | **16 KB** (0x4000) |
| 实际可用堆 (物理上限) | ~88 KB (RAM - BSS - 栈保留) |
| `_sbrk` 边界 | `_estack - 0x2000` (栈底上 8KB) |

### 启动时分配明细

**Gimbal 对象 (~7.8 KB):**
| 组件 | 大小 | 说明 |
|------|------|------|
| 7 个 PID 对象 | ~4.9 KB | 每个 PID 内嵌 3 个 FuzzyInfer (含 49-int 规则表) |
| MahonyAhrs | ~130 B | 四元数+欧拉角+临时变量 |
| Referee 协议 | ~1.2 KB | 协议结构体 + FSM + 缓冲区 |
| DeviceManager × 4 | ~940 B | etl::vector 内联存储 |
| 其他 (Gimbal2Dof, Shoot2Fric, 数组, 指针) | ~650 B | dataBox[128], spaver[10] 等 |

**外部分配 (~13.2 KB):**
| 组件 | 大小 | 说明 |
|------|------|------|
| ThrottledCan<128> × 2 | ~8.8 KB | 队列缓冲区 (128 元素优先级队列) 在堆上 |
| Serial<128> × 3 | ~1.9 KB | 双缓冲区 + etl::vector |
| 电机 × 5 (GM6020, DM, M3508×2, M2006) | ~600 B | CanDevice + 状态字段 |
| IMU × 2 (BMI088, HipnucImuCan) | ~180 B | SpiDevice + 传感器数据 |
| 遥控器 (DR16, VT03) | ~250 B | 设备基类 + 数据 |
| 运行时 STL 容器 | ~0.5 KB | unordered_map, vector (设备注册时分配) |

**总计: ~21.5 KB**

### 结论

| | 值 |
|------|-----|
| 链接器声明最小堆 | 16 KB |
| 实际使用 | **~21.5 KB** |
| 物理上限 | ~88 KB |
| 当前安全余量 | ~66 KB |

`_Min_Heap_Size` (16KB) < 实际使用 (21.5KB)，但 `_sbrk` 不强制执行此最小值。当前能运行仅因为物理 RAM 余量充足。**失去编译期保护**——BSS 增长后链接器不会告警，堆可能静默耗尽。

## 三、BSS 段越界分析 (已修复)

### 修复前的内存布局

```
0x200004f0  Aimbot          49B   全局自瞄数据
0x20000521  *fill*           3B   链接器对齐
0x20000524  GimbalImu       29B   全局 IMU 数据
0x20000541  *fill*           3B
0x20000544  x[50]           50B   ← 死代码 (只写不读)
0x20000576  Eigen::fix<1>    ?B   ← 被踩: Eigen 内部哨兵值
0x2000057c  LED_Data        16B   ← 被踩: WS2812b 颜色
0x2000058c  LED_Mod         16B   ← 被踩: WS2812b 亮度
0x2000059c  pwmData        292B   ← 被踩: WS2812b DMA 缓冲区
0x200006c0  (blast end)           ← 最坏 len=255 溢出止于此
0x20000758  gimbal*          4B   ← 安全 (超出 blast radius)
```

### 越界向量

`UsbReceive()` 中 `std::copy(rx_data, rx_data + len, x)`：
- `len=50`: 刚好填满 x[50]，不越界
- `len=51`: 多写 1 字节，踩到 `Eigen::fix<1>`
- `len=255`: 多写 205 字节，踩穿 Eigen + LED + pwmData 前 163 字节

### 最危险后果

`Eigen::fix<1>` 是 Eigen 库标记「编译期固定大小」的哨兵值。被踩坏后，所有 `Matrix<float,3,1>` 等固定大小运算静默出错 → `ComputeFf()` 前馈力矩算出随机值 → 直接注入电机电流指令 → **云台随机抽动**。

### 修复

见 `已修复_变更记录.md` — F04。

## 四、两类堆内存吞金兽

1. **ThrottledCan<128> 队列** (`etl::priority_queue`): 每个 ~4.4 KB，两个合计 ~8.8 KB。128 条 CAN 消息的缓冲对 500Hz 控制回路偏大。

2. **PID 模糊规则表** (`FuzzyInfer`): 每个 PID 内嵌 3 个 49-int 查找表 (~588 B/PID)，7 个 PID 合计 ~4.1 KB。可考虑将表格移到 Flash（`static constexpr`），释放相同大小的 RAM。

**两项合计: ~12.9 KB，占总堆的 60%。**

## 五、关键风险汇总

| 风险 | 严重程度 | 当前状态 |
|------|----------|----------|
| BSS 越界 (x[50] 溢出踩 Eigen) | 严重 | ✅ 已修复 F04 |
| `_Min_Heap_Size` 与实际不符 | 严重 | ❌ 待修复 C03 |
| NaN 穿透到电机电流 | 严重 | ❌ 待修复 C02 |
| ISR 竞态 (USB/CAN vs 定时器) | 高 | ❌ 待修复 C04/C05 |
| 堆分配无 OOM 检查 | 中 | ❌ 待修复 C16 |
| 堆碎片化风险 (STL 容器) | 低 | 长期关注 |
| 栈溢出 | 无风险 | 8KB 只用 1.2KB |
