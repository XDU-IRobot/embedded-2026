## 严重 (可导致电机失控或系统挂起)

### C01 · BxCan::Write() 无超时自旋锁死

**文件**: `libs/librm/src/librm/hal/stm32/bxcan.cc:149-150`

```cpp
while (HAL_CAN_GetTxMailboxesFreeLevel(hcan_) == 0) { }
```

无超时忙等待。CAN 拥塞时整个系统永久挂起。仿照 `fdcan.cc:217-237` 添加 ~500μs 超时+重试。

**后果**: 三个 TX 邮箱全满时，整个微控制器卡死——500Hz 控制回路停、看门狗不触发。

---

### C02 · NaN 从瞄准数据直接穿透到电机电流

**涉及文件**: `Usb.cc` → `Acontrol.cc` → `pid.cc` → `dm_motor.hpp`

```
NUC 发来 NaN(float)
  → Aimbot.TargetYawAngle = NaN
  → gimbal_controller.Update(NaN, ...)
  → PID 产生 NaN
  → Clamp(NaN, limits) = NaN     ← Clamp 对 NaN 无效
  → SetCurrent((int16_t)NaN)     ← 未定义行为（通常 = -32768 或 0）
  → 电机收到随机满电流
  → 云台猛抽
```

**修复方案**（任选）:
1. `UsbReceive()` 中解包后对每个 float 字段做 `std::isfinite()` 检查
2. `PID::Update()` 入口处检查输入 NaN，拒绝更新
3. `FloatToInt()` 中添加 `std::isfinite(x)` 守卫

**后果**: NUC 端任意浮点异常无阻碍穿透到电机电流指令，表现为偶发剧烈跳动。

### C03 · `_Min_Heap_Size` 与实际堆使用量不匹配

**文件**: `STM32F407XX_FLASH.ld`

| | 配置值 | 实际值 |
|---|---|---|
| `_Min_Heap_Size` | 16 KB (0x4000) | — |
| 启动时实际分配 | — | **~21.5 KB** |
| 物理可用上限 | — | ~88 KB |

链接器声明的 16KB 低于实际 21.5KB。`_sbrk` 不强制执行此限制，当前没崩仅因为物理 RAM 余量充足。但链接器无法在未来 BSS 增长（新增传感器缓冲区、协议结构体）时发出编译期告警。

**修复**: `_Min_Heap_Size = 0x6000` (24 KB)，匹配实际使用量。

**后果**: 不修不会立即炸，但失去了编译期安全网。BSS 段增长后堆空间被挤压，`new` 静默返回 `nullptr`，运行时随机崩溃。

## 高 (可导致控制异常或数据损坏)

### C04 · ISR 竞态: USB 接收 vs 500Hz 控制回路

**文件**: `Usb.cc` (USB ISR) vs `Acontrol.cc` (定时器 ISR)

```cpp
// Acontrol.cc — 500Hz 定时器 ISR 中分步读取 Aimbot
rc_yaw_data   = Aimbot.TargetYawAngle;   // ← 数据包 N
// USB ISR 在此时抢占，memcpy 写入数据包 N+1
rc_pitch_data = Aimbot.TargetPitchAngle;  // ← 数据包 N+1
```

yaw/pitch 来自不同自瞄帧，速度和位置不匹配 → 前馈量计算错误。

**修复**: 在定时器 ISR 入口用 `memcpy` 获取 `Aimbot` 的本地快照，或利用 ISR 优先级保证原子性。

---

### C05 · ISR 竞态: CAN 接收 vs 控制回路

**文件**: `dji_motor.hpp` (CAN ISR) vs `Acontrol.cc` (定时器 ISR)

```cpp
yaw_ = yaw_motor->pos_rad();    // CAN 帧 N 的编码器
// CAN ISR 更新为帧 N+1
rpm  = yaw_motor->rpm();        // CAN 帧 N+1 的转速
```

位置和转速来自不同 CAN 帧 → PID 速度环收到错误的速度反馈 → 微分项跳变。Cortex-M4 单字段 32-bit 访问是原子的，但跨字段读取不是。

**修复**: 同上——在控制函数入口批量快照电机状态。此外 `encoder_`/`rpm_` 字段加 `volatile`（见 C06）。

---

### C06 · CAN ISR 共享数据缺少 volatile

**文件**:
- `libs/librm/src/librm/device/actuator/dji_motor.hpp:304-310` — `encoder_`, `rpm_`, `current_`, `temperature_`
- `app/common/aimbot_comm_can.hpp:25-31` — `aimbot_state_`, `yaw_`, `pitch_`, `nuc_start_flag_`

CAN ISR 写入、主循环/定时器 ISR 读取，均非 `volatile`。LTO 优化下编译器可能将值缓存在寄存器中，主循环永远读到旧值。

**修复**: 声明为 `volatile` 或使用 `std::atomic`。

---

### C07 · 偏航前馈硬编码偏移与类成员不一致

**文件**: `Acontrol.cc:70` vs `gimbal.hpp:46`

```cpp
// Acontrol.cc:70 — 硬编码
-rm::modules::Wrap(yaw_motor->pos_rad() - 5.14, -M_PI, M_PI)

// gimbal.hpp:46 — 类成员
float yaw_center_encoder = 5.174;
```

差值 ~0.034 rad ≈ 2°。校准 `yaw_center_encoder` 后硬编码不会自动同步。

**修复**: 使用 `drone_gb.yaw_center_encoder` 替代 `5.14`。

### C08 · 镜头堵转检测阈值过于严格

**文件**: `Acontrol.cc:399-401`

```cpp
constexpr int kStallThreshold = 3;  // 8ms 内 3 个编码器计数
```

M2006 @500RPM 每 8ms 移动 ~544 计数。3 计数阈值在加速瞬态、CAN 帧丢失、<22 RPM 低速时误触发。

**修复**: 改为 ≥50 计数，或改为基于时间的超时（100ms 内无运动）。

## 中 (影响正确性或鲁棒性)

### C09 · USB 断连后陈旧数据继续驱动

**文件**: `Acontrol.cc`

`Aimbot.SystemTimer` 由 NUC 填充但**从未被读取**。USB 断连后 `Aimbot` 保持最终值，控制回路继续运行。在手动模式中 `Aimbot.YawSpeed * 78.0f` 前馈项保持非零 → 云台向一个方向持续漂移。

**修复**: 检查 `SystemTimer` 是否递增，超时（如 >50ms 未更新）则丢弃数据或切回无力模式。

---

### C10 · 手动模式错误使用 Aimbot.YawSpeed 前馈

**文件**: `Acontrol.cc:72` (CONTROLLER_CHOICE == 1 分支)

```cpp
// 手动模式下仍然加了 NUC 的速度前馈
yaw_tau2voltage = tau_ff.x() * 2530.0f + Aimbot.YawSpeed * 78.0f;
```

手动模式不需要 NUC 的速度前馈。自动→手动切换后陈旧 `Aimbot.YawSpeed` 残留，产生恒定偏航偏置电流。

**修复**: 手动模式路径移除 `Aimbot.YawSpeed` 项，或切手动时清零该字段。

---

### C11 · CAN 帧损坏导致 DM 电机反馈跳变

**文件**: `dm_motor.hpp:238-240`

CAN 帧受干扰 → `IntToFloat(p_int, ...)` 解码出垃圾浮点位置 → PID 闭环基于错误反馈 → 电机跳向错误位置。

**修复**: `IntToFloat` 对输入做合理性检查（与上次值变化量 < 阈值则丢弃），或在 DM 电机类中添加滑动窗口滤波。

### C12 · DM 电机 FloatToInt 无 NaN/Inf 防护

```cpp
int FloatToInt(f32 x, f32 x_min, f32 x_max, int bits) {
    return (int)((x - offset) * ((f32)((1 << bits) - 1)) / span);
```
